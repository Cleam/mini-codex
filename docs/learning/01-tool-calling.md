# 01：工具调用（Tool Calling）

状态：代码复盘已补齐，真实调用验收与个人理解确认待完成。整理日期：2026-10-19。

## 本阶段学习目标

看清“模型提出调用意图，本地程序校验并执行，结果重新进入模型上下文”的最小闭环。只做 `list_files` 与 `read_file`，不引入循环或框架。

## 已实现什么

`main.ts` 构造消息与工具描述，`client.ts` 请求模型并校验响应。入口查找工具、解析 JSON；`defineTool` 用 Zod 校验参数，工具通过 Node.js 文件 API 执行。结果带 `tool_call_id` 写回 messages，再请求模型组织回答。控制台显示摘要，JSONL 保留过程。

## 核心原理

- 工具描述（Tool Schema）给模型看，帮助它选择工具、生成参数，不等于授权或执行。
- 工具在本地 Node.js 进程执行；模型输出的名称、JSON 与参数都必须校验。
- assistant 的 tool_calls 与 tool 消息的 tool_call_id 配对，构成协议上下文。
- 模型 API 请求不会自动获知本地副作用，工具结果必须显式回传。
- 结构化输出（Structured Output）约束输出形状；工具调用表达调用外部能力的意图，两者不是同一件事。

## 为什么这样设计

原生 fetch 让请求结构可见；数组与 Map 足以管理两个工具；`defineTool` 将校验与执行绑定。工具错误作为结果返回，方便模型理解失败原因。固定一轮工具调用用于先学习协议，多轮决策留到 v0.3。
